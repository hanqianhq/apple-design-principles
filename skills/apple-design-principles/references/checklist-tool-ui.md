# 工具类 / SaaS / 后台检查表（Operate）

> 用户来这里是为了**把事做完**：管理资产、处理订单、跑任务、协作。苹果式在这里的含义是「可信、可预期、不添乱」，而不是「漂亮的营销感」。
> 排序原则：**真实 > 走得通 > 安全 > 一致 > 好看**。T1–T5 的问题默认至少是 P1，涉及数据真假、不可逆、扣费、权限的默认 P0。
> 平台数值另见 [checklist-web.md](checklist-web.md) / [checklist-ios.md](checklist-ios.md)；文案写法见 [ux-writing.md](ux-writing.md)。

## 目录
T1 数据真实｜T2 计数、分页与筛选一致｜T3 危险与不可逆操作｜T4 长任务｜T5 计费与用量透明｜T6 权限｜T7 术语表与命名一致｜T8 资产与引用关系｜T9 承诺与能力一致｜T10 状态完整｜T11 结构与导航｜T12 协作与可追溯｜T13 审查输出要点

## T1. 数据真实（默认 P0）
- [ ] 界面上没有开发时写死的示例数据、占位人名、假活动、假通知红点
- [ ] 没有数据就显示**诚实的空状态**（说明内容会怎样出现 + 一个入口），而不是演示数据
- [ ] 占位图明确标为「无图」或用中性占位，不让多个对象共用一张看似真实的图
- [ ] 演示 / 沙盒模式要有明显标识，并能一键退出

## T2. 计数、分页与筛选一致（默认 P0–P1）
- [ ] 标题计数、标签页角标、表格行数、分页总数、导出条数**来自同一个查询**
- [ ] 筛选 / 搜索后，计数和页码同步更新，并说明筛选条件（「共 0 个 · 已筛选：本周」+「清除筛选」）
- [ ] 结果为 0 时显示「没有符合条件的结果」而不是「暂无数据」，并给出放宽条件的办法
- [ ] 批量选择时写清范围：「已选本页 20 个」vs「已选全部 128 个」
- [ ] 数字格式统一（千分位、单位、时区），时间显示相对 + 悬停看绝对时间

## T3. 危险与不可逆操作（默认 P0）
- [ ] 删除、清空、覆盖、退订、转让等操作**和常用操作在空间上分开**（放「更多」菜单或页面底部的危险区），不和「导出」「保存」相邻
- [ ] 执行前说明**影响范围**：对象名、数量、会连带影响什么（「6 个订单正在引用这个模板」）
- [ ] 首选可恢复：回收站 / 「最近删除」保留一段时间，或操作后提供「撤销」；真的不可逆才用强确认（输入名称确认）
- [ ] 确认弹窗：标题是具体问题，按钮写具体动作（「删除 128 个资产」/「取消」），破坏性按钮用破坏性样式，默认焦点不在破坏性按钮上（见 [ux-writing.md](ux-writing.md)）
- [ ] 对应 WCAG 3.3.4：删改用户数据的提交要可撤销、可检查或可确认

## T4. 长任务（导出、生成、导入、批处理）
- [ ] 点击后立即反馈（按钮变状态），超过几秒显示**真实进度**（百分比、已完成 / 总数、预计剩余），不能只转圈
- [ ] 任务在后台继续：刷新、关页、切换页面后能在「任务 / 下载中心」找到它和它的状态
- [ ] 完成或失败时通知（站内通知 + 可选邮件 / 推送），带结果入口
- [ ] 部分失败要说清哪些成功、哪些失败、失败原因，并能只重试失败的部分
- [ ] 可取消；取消后说明已产生的结果和费用如何处理
- [ ] 提交前给出预估：大小、耗时、费用（见 T5）

## T5. 计费与用量透明（默认 P0）
- [ ] 会扣费 / 扣点数的操作，**在按钮上或旁边事先显示**消耗量（「导出 · 消耗 20 点」）
- [ ] 余额不足时提前提示，而不是执行到一半失败；失败的任务是否扣费要写明
- [ ] 有用量记录（时间、操作、对象、消耗、余额），和账单页数字一致
- [ ] 套餐限制（数量、容量、席位）在接近上限前提示，说明超出后会怎样

## T6. 权限
- [ ] 没有权限的操作：**不显示**，或置灰并写明原因和找谁开通（「仅工作区所有者可删除工作区」）——不能点了才报错
- [ ] 角色说明能在界面里查到（谁能看、谁能改、谁能删）
- [ ] 邀请、移除成员、改角色等操作有记录（见 T12）
- [ ] 无权访问的页面给出申请入口，而不是 404 或空白

## T7. 术语表与命名一致（默认 P1）
- [ ] 建一张术语表：**一个概念一个词**，列出「用这个词 / 不用这些同义词 / 定义」（模板见 [ux-writing.md](ux-writing.md)）
- [ ] 数据结构层级用户只需记住 2–3 层（如「工作区 → 项目 → 资产」），每层名字固定
- [ ] 同一个动作全流程同名：按钮「发布」→ 提示「已发布」→ 列表状态「已发布」
- [ ] 不把内部编号、表名、状态码、英文枚举值（`job_id`、`PENDING`）直接露给用户
- [ ] 中英文版本各自统一，不在中文界面混用英文术语（专有名词除外）

## T8. 资产与引用关系（资产库 / 素材库 / 模板库类产品）
- [ ] 每个资产显示**准确的引用数**，点开能列出引用它的对象（哪些订单 / 项目 / 页面）并可跳转
- [ ] 删除或替换被引用的资产前，列出受影响对象，提供「替换为…」或「仅解除引用」
- [ ] 跨项目复用是正常操作：标明来源，不当成错误标红
- [ ] 正文里的 @ 引用或链接直接打开那个资产，而不是只到分类列表
- [ ] 筛选维度覆盖真实找法：按项目、类型、是否有图、是否被引用、修改人、修改时间
- [ ] 版本：能看到修改记录，能回到旧版本

## T9. 承诺与能力一致（默认 P0）
- [ ] 官网、落地页、应用商店描述、邮件里的承诺（免费、开放注册、支持格式、上限）与产品当前实际一致
- [ ] 未上线的功能不出现可点击入口；预告要标「即将推出」且不可误操作
- [ ] 定位一句话全站统一（首页、登录页、空状态、帮助文档）

## T10. 状态完整
- [ ] 每个关键页面都设计了：空、加载、部分加载、出错、离线、无权限、超大数据量
- [ ] 报错说清三件事：发生了什么 / 数据还在不在 / 下一步怎么办（见 [ux-writing.md](ux-writing.md)）
- [ ] 自动保存有可见状态（「已保存 · 刚刚」），离开有未保存内容时提醒

## T11. 结构与导航
- [ ] 一套主导航；入口不重复；当前位置清楚（面包屑或标题）
- [ ] 主流程有进度感：用户知道自己在第几步、下一步是什么
- [ ] 每页一个主操作；次要操作收进菜单（#21 渐进披露）
- [ ] 键盘可完成高频操作；提供快捷键时在菜单或提示里可发现

## T12. 协作与可追溯
- [ ] 显示最后修改人和时间；重要对象有活动记录
- [ ] 共享对象被他人修改或删除时，相关成员能收到通知
- [ ] 冲突编辑有提示，不静默覆盖

## T13. 审查输出要点
- 先报 T1 / T3 / T5 / T9 的 P0，再报体验问题
- 每条写证据（位置、截图里的原文或数字），看不到的状态列入「待确认」
- 改法优先给「降低风险」的方案（可撤销、可预估、可追溯），再给文案
